How to add page numbers to a PDF without uploading it

SQLViz · September 2026

Page numbers look like a trivial feature until a document has to be filed, signed, referenced or printed. A viewer shows a page counter, but that counter belongs to the program, not to the file. Print the document, email it, or hand it to a portal and the numbers are gone. Then somebody has to write “see page 14” in an email about a page that has no 14 printed on it.

Page numbers in the SQLViz toolkit writes the number into each page at the position and size you choose, inside your browser. Nothing is uploaded, which matters when the document being numbered is a contract, a tender, or anything with a client’s name on it.

Where the number should sit

The right position depends on how the document will be used, and it takes ten seconds to choose well.

  • Bottom centre is the default that suits reports, proposals and anything read on screen. It is out of the way and impossible to miss.
  • Top right is standard for drawings, specifications and contracts that get stapled or clipped, because the top right corner stays visible when pages are stacked.
  • Inside a margin, never on the text. Before you run it, look at the first page and the last page. Where is the existing footer? Where is the letterhead? Put the number in empty space, and leave 15–20 mm from the paper edge if the document will be hole-punched or stapled — punching a hole through page 27 is a small mistake that is impossible to unmake.

The cover page problem

Almost no report wants “1” printed on its cover. Page numbers writes on every page, so there are two ways to handle it:

  • Use the start number to keep the printed number honest. The tool has a start number, so a document whose cover page is already counted can begin at 2. The cover still carries a number, but every number matches the position in the file, which is what anyone citing the document actually needs.
  • Number only the part that needs it. Split off the cover and the body into two files with a range list of 1-1, 2-30 (write the real last page number), number only the body starting at 2, then put the cover back in front with the free merge tool. Three steps, and it is the only way to leave the cover completely unnumbered.

Roman numerals for front matter are a different situation. Numbering tools work in the numbering system the document uses, so roman front matter is usually produced in the word processor before export, or by building the front matter as its own short document, numbering it, and merging it in place. It is manual work, and it is the reason most teams number everything in arabic and accept that the contents page says “3” instead of “iii”.

Do the destructive edits first

This is the ordering rule that saves the most rework: delete, reorder, rotate, then number.

If you number a 40-page document and then remove two pages, every number after the cut is wrong, and the tool cannot know it. You would number the file again — this time on top of the existing numbers, which leaves you with two numbers on each page. The fix is to go back to the unnumbered copy and start over, which is exactly the work you were trying to avoid.

So: finish with removing pages and rotation, then number what is left. Numbering should be the last step before you send the file, and the file you number should be the one you intend to keep.

Step by step

  1. Make a copy of the finished document first. Keep the unnumbered version until you are happy with the result — once a number is written into a page, the only clean way to take it back is to start from the copy.
  2. Open the PDF tools page and choose Page numbers.
  3. Add the PDF and choose the position and the font size. Bottom centre is the default; top right suits anything that gets stapled or clipped. Slightly smaller than the body text is almost always right — the number should be findable, not loud.
  4. Run it and download. Then check three pages: the first numbered page, the page after it, and the last page.
  5. Compare against anything that refers to pages. A table of contents, a signed signature page, a form that says “page 2 of 5”. If a reference now points at the wrong page, you have found a document problem the numbering just made visible.

What to check on the result

Open the file at 100% zoom, not fit-to-window. Collisions with an existing footer or a date stamp show up at full size and disappear in a zoomed-out thumbnail.

Look for numbers that were already there. Many scans and almost all generated invoices already carry a page number. If the document had one, you will now have two, and the new one is drawn into the page so it cannot be toggled off in a viewer. When that happens, do not try to cover it; start again from the original file and either number only the pages that lack a number or accept the existing numbering.

Print one page. Screen and paper disagree about margins, and the print preview is the place where a number placed too close to the edge reveals itself.

Page count versus last printed number. If the final page prints “12” and the viewer says 13 pages, there is an unnumbered page somewhere — often the back of the cover — and it is worth a minute to find out why.

Page numbering is not Bates stamping

Legal discovery uses Bates numbering: a unique, prefixed identifier on every page of a large production, so that every page of every document can be cited unambiguously. If the numbering has to be legally defensible — on a production of thousands of pages, with a prefix and a fixed digit count — use a tool built for that job. A page-number tool makes a document easier to navigate; it does not create an evidence trail.
